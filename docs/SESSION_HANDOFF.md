## Ноу-хау сессии 9

- **Проверять не наличие гейта, а его резолв**: `eslint --print-config <файл>` печатает итоговый набор правил — единственный честный ответ на вопрос «правило вообще существует». `pnpm lint` в Next 15 падает только на `error`; всё, что в конфиге стоит `warn` (у нас `no-unused-vars`, `no-explicit-any`, `exhaustive-deps`), гейтом не является.
- **Маркер смоука должен зависеть от данных.** Любая строка из JSX — не маркер контента, а маркер того, что Next вообще ответил. Брать надо разметку, которая рендерится только по непустому результату запроса (`event__content`, `venue__time`).
- **Красный прогон дешевле устраивать локально**: `pnpm lint` / `pnpm typecheck` в CI вызываются дословно теми же скриптами, поэтому нарушение + откат на dev-машине доказывает гейт без мусора в истории. Для `pnpm build` так не выйдет — ему нужна поднятая БД.
- SSH к боксу с dev-машины опять в просадке (`banner exchange`), HTTP наружу глушится DPI. Рабочий обход — **`ssh -o ProxyJump=GONBA sabantuy '<команда>'`**: короткая форма через алиасы `~/.ssh/config`, разворачивать ProxyCommand с явными ключами (как записано в handoff сессии 8) не нужно.
- **Проверять надо и то, что стоит над гейтами.** Флаг «защита ветки включена» — такое же утверждение, требующее показанного красного, как и `lint`: при `enforce_admins: false` push админа проходит, лишь печатая «Bypassed rule violations».
- **PowerShell не годится для правки YAML и любых файлов с кириллицей**: `Set-Content -Encoding utf8` в 5.1 добавляет BOM (GitHub перестаёт видеть `workflow_dispatch`), а `Get-Content`+`Set-Content` перекодирует русский текст в mojibake. Править только Edit/Write.
