## Правила работы, которые легко нарушить

- **Прямой push в `main` не проходит** (branch protection + `enforce_admins: true`). Любая
  правка — веткой и PR с зелёным `build`, это касается и коммитов в `docs/`.
- **Новые Payload-миграции** — применить на прод **вручную до деплоя** (#017), затем
  `gh workflow run deploy-prod.yml`. Пуш-гейт миграции отклонит деплой сам, это ожидаемо.
- **Публичный репозиторий — recon-поверхность.** Значения — в KARMAN и `~/.ssh/config`, в
  репозиторий не попадают ничего, включая логи и диагностические дампы.

## Ноу-хау сессии 16

- **`payload run` только ИМПОРТИРУЕТ модуль** и не зовёт `export default`. Скрипт выглядит
  выполненным, ничего не делая. Работать надо на верхнем уровне модуля.
- **`GET /grants` не находит то, что сам же предлагает.** Шесть прогонов подряд держал только
  `409` от КАРМАНА; наш фильтр по полям не ловит форму ответа.
- **Проверка через API может покраснеть на успешной записи.** `payload.update` пишет
  `reset_password_requested_at`, а `findByID` отдаёт `undefined` — поле скрыто из ответов.
- **`pnpm 11+` не читает `pnpm.overrides` из `package.json`.** Под `packageManager: pnpm@10.15.0`
  работает, на pnpm 12 закрытые high вернутся молча.
- **Первый красный прогон нового гейта не покраснел.** Ответ `550` сразу после `250` nodemailer
  проглатывает; красным пришлось сделать отказ по существу.
- **Журнал прогона отдаётся не весь:** `gh run view --log` вернул два шага из семи, полный —
  через `gh api …/actions/jobs/<job-id>/logs --allow-escape-sequences`.
- **Пароль в строке подключения содержит `/`** — имя БД берётся строго после последнего `@`.
- **`headers()` в `next.config.js` асинхронная** (`withPayload` оборачивает): возвращает промис.
  Синхронный разбор даёт пустой объект и «успешный» тест, который ничего не проверяет.
- **`redirect_uri` и origin ЕСА — два разных адреса.** Первый — наш домен, куда ЕСА возвращает
  посетителя; второй — чужой, куда форма постит. Тест, сравнивающий их между собой, ищет
  ошибку там, где её нет: так и вышло.
- **Проверка «аноним не прочитал» может быть вакуумной**, если взять несуществующий метод
  клиента: падение одинаково и при запрете, и при разрешении.
