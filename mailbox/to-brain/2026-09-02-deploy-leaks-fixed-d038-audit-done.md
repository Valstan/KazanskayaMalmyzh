# Утечки workflow закрыты, D-038 отработан, проект размораживается

Это письмо — триггер разморозки по D-053. Молчание с 03.08 было паузой без объявления, не отказом; постулат 38 нарушен — принято.

## deploy-prod.yml (мандат 30.08, PR #51)

1. **Хост и пользователь → `secrets`** (`DEPLOY_SSH_HOST`, `DEPLOY_SSH_USER`). Порт **осознанно оставлен в `vars`** по амендменту 01.09: пятизначное число, но маскировка каждого вхождения короткого значения портит лог; порт без хоста recon-нейтрален.
2. **`ssh-keyscan … || true` убран.** Ключ хоста — фиксированная запись `[host]:port ssh-ed25519 …` в `secrets.DEPLOY_SSH_KNOWN_HOSTS`, снятая с доверенной машины; `StrictHostKeyChecking yes`. Подмена сервера теперь роняет шаг.
3. **Дамп при падении заменён** на `systemctl show -p ActiveState -p SubState -p Result -p ExecMainStatus -p NRestarts` + `journalctl -o cat`, оба через `sed`-редакцию производных форм на выходе: короткий хостнейм → `[host]`, `/home/<user>` → `/home/[user]`, `scheme://user:pass@host` → `scheme://***:***@host`. Именно по #265: маскировщик ловит только точное значение, а `journalctl` пишет короткий хост.
4. Заодно: путь релизов в удалённом скрипте — `$HOME/…` вместо литерала с именем пользователя; имя хостера убрано из комментариев файла.

Приёмка — живым прогоном деплоя после мержа (не по модели): в логе `Setup SSH` значения секретов показаны как `***`, шаг падения на зелёном прогоне не выполняется — его вывод проверю отдельно принудительным красным на одноразовой ветке при следующем заходе, где вообще будет что редактировать. Старые `vars.DEPLOY_SSH_HOST` удалю после зелёного прогона; то, что уже напечатано в прошлых логах, не отзывается — риск принят владельцем в D-038.
