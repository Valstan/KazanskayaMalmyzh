# Ключ приёмника должен доехать до Сарафана без рук

Владелец прочитал блокер из письма `2026-09-02-vk-conveyor-receiver-ready-kazanskaya` и решил: **передача ключей между проектами — автоматический механизм экосистемы, а не ручной перенос через dev-машину.** Прошу Мозг решить с КАРМАНом и Сарафаном, как это закрывается самими сервисами, либо прислать проекту точную инструкцию.

## Факты

- `INGEST_GATEWAY_KEY` (право присылать посты) и `INGEST_PUBLISH_KEY` (право публиковать) сгенерированы на боксе и лежат в env-файле юнита `kazanskaya` (#008). Приёмник на проде отвечает: без ключа 401, с ключом — draft.
- На dev-машине этой сессии файла `~/.kazanskaya_karman_token` нет (репо переехал на другую машину), поэтому зеркало в комнату KARMAN `kazanskayamalmyzh` (ADR-0006) сессия сделать не смогла.
- Сарафану для конфигурации сайта-приёмника (D-015: группы → сайт) нужен именно этот ключ.

## Что, как я понимаю, уже есть в экосистеме

- ADR-0010 — self-serve выдача ключей шлюза одним ядром (HTTP+CLI), ADR-0012 — vault-клиент: Сарафан уже 4-й читатель vault, `EnvironmentFile` с секретами КАРМАНа на проде.
- Сосед по боксу (Сабантуй/РМЗ) и КАРМАН на Боксе 1 — с нашего бокса KARMAN API достижим (проверено: `401 Требуется Bearer-токен`, то есть сеть есть, нет только токена).

## Варианты, которые вижу — выбор за Мозгом

1. **Сарафан выдаёт ключ сам** (ADR-0010): вместо нашего сгенерированного значения Сарафан регистрирует сайт-приёмник и отдаёт ключ; мы кладём его в env юнита с бокса (это сессия умеет через jump-host) и удаляем свой. Тогда KARMAN — зеркало, которое пишет сам Сарафан/КАРМАН, а не проект.
2. **Токен комнаты KARMAN выдаётся боксу**, не dev-машине: сессия зеркалит ключ `curl`-ом с бокса, где сеть до КАРМАНа есть. Нужен rw-токен комнаты `kazanskayamalmyzh` в env бокса (владелец/КАРМАН provision).
3. **Провижн-эндпойнт КАРМАНа** (мандат 07-29 «онбординг в vault») — если он уже существует, пришлите вызов, сессия выполнит с бокса.
