# Три находки сессии 20 — все с измерением, не мнением

## 1. Кириллица через SSH-хопы — только base64-конвертом

Двойной хоп (dev → jump → бокс) манглит stdin дважды: внутренние двойные
кавычки исчезают (curl ушёл не на тот URL — в `-v` видно `GET /` вместо
`/program` и коннект на внешний IP), `\n` превращается в `n`, кириллица в
паттернах — в `?` (запрос `LIKE '%единственный%'` молча вернул ноль, хотя
строка в базе есть). Плюс `Get-Content` без `-Raw` вставляет CRLF в пайп —
bash давится `\r`. Рецепт: удалённый скрипт — файлом в LF, пайп через
`Get-Content -Raw`, кириллица и JSON — только в файле, а значения для SQL —
base64 внутрь скрипта с `base64 -d` на месте (`UPDATE ... SET summary` одним
полем так и ушёл, BEFORE/AFTER сошлись). Одиночный хоп кавычки держит —
правило именно про двойной.

## 2. Webfetch дорисовывает preload — проверять по origin

Снапшот главной через webfetch показал 10 `<link rel="preload" as="image">`
и чуть не уехал в задачу «ужать preload». Проверка тремя путями: origin
(:3001) — preload только eager (у галереи ровно 4 первых кадра секций,
корректно), снаружи через прокси — ноль, с браузерным UA — ноль. Вывод:
дорисовка пайплайна webfetch, на проде чинить нечего. Правило: любая
«оптимизационная» находка из чужого снапшота подтверждается origin-замером
до заведения задачи.

## 3. Каждый деплой перезапускает ISR-окно — наблюдать через час

`sitemap.xml` с `revalidate = 3600` после выкатки отдаёт build-пререндер
(пустая сборочная БД — null'ы) до первого окна; рестарт юнита кэш не
сбрасывает (файл в бандле). Три деплоя подряд 08.10 так и гоняли друг друга:
каждая проверка попадала в свежие null'ы. Даты (`max(updatedAt)` из живой БД)
появились только когда одна сборка прожила свой час. Правило: ISR-утверждения
проверяются минимум через окно после ПОСЛЕДНЕГО деплоя, а в handoff пишется
время, после которого смотреть.
